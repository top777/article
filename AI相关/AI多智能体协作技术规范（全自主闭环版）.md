# AI多智能体协作技术规范（全自主闭环版）

**版本**：v3.0-Final  
**生效日期**：2026-08-02  
**核心理念**：零人工干预、全自主决策、闭环自演进、极致资源效率

---

## 前言

本规范面向基于大语言模型（LLM）的多智能体协作系统，在整合缓存复用、Token优化、自改善进化等机制的基础上，**彻底消除所有人工介入节点**，构建一套由智能体自主完成“感知→决策→执行→校验→修复→进化”全链路的工程范式。所有规则、阈值、策略均由系统内部动态生成与调整，无需人类在环（Human-in-the-Loop）。


## 1. 核心架构：协同工程范式

### 1.1 角色矩阵与正交分工

- **RACI模型映射**：为每个智能体定义严格的岗位说明书，明确责任（R）、批准权（A）、咨询（C）、知情（I）边界。
- **正交性原则**：确保各角色领域互不重叠，消除资源竞争与决策冲突。基础角色矩阵包括：

| 角色 | 职责 | 核心产出 |
| :--- | :--- | :--- |
| **Leader（经理）** | 任务拆解、团队调度、决策仲裁、全局管控 | 结构化任务计划、调度指令 |
| **Planner（规划师）** | 子任务路径设计与资源预算 | 执行蓝图（JSON） |
| **Coder（编码员）** | 代码/脚本生成与修改 | 可执行代码产物 |
| **Tester（测试员）** | 单元测试、集成验证、回归检查 | 测试报告与缺陷单 |
| **Checker（校验官）** | 事实核查、风格检查、安全扫描 | 校验评分与退回指令 |
| **Explorer（探索者）** | 低权重实验、新策略试错 | 改进提案与实验数据 |
| **Evaluator（评估官）** | 多维绩效评分、改进有效性判定 | 质量评分与等级标签 |
| **CacheManager（缓存官）** | 缓存读写、失效淘汰、命中率优化 | 缓存统计与调度建议 |
| **Negotiator（调解官）** | 冲突调解、委员会投票组织 | 共识决议或保留意见 |

### 1.2 Leader-Teammate 分级架构

- **Leader智能体**：全局唯一（或通过Raft选举产生热备），负责任务理解、团队组建、计划审批、异常仲裁与全生命周期管控。Leader拥有最终裁定权，但其决策受“仲裁链”约束（见5.2节）。
- **Teammate智能体**：各司其职，并行执行，通过共享工作区与消息总线实时同步状态。
- **自主协同**：支持状态持久化、断点续执与实时可观测，全流程无人干预。

### 1.3 规则即代码的全局约束

- **规则文件化**：使用 `.mdc` 后缀文件定义标准化作业流程（SOP），纳入Git版本控制。
- **分类注入**：
  - **始终应用规则**（`always.mdc`）：安全红线、代码规范、隐私条款等，注入所有智能体上下文。
  - **文件触发规则**（`globs/*.mdc`）：按文件类型匹配（如React组件、SQL脚本），实现关注点分离。
- **规则自演化**：任何智能体均可通过“改进提案”流程申请修改 `.mdc` 文件，经Leader批准后自动生效（见4.2节）。


## 2. 执行流程：可编排工作流

### 2.1 管道化任务编排

- **标准循环**：计划（Plan）→ 执行（Do）→ 检查（Check）→ 行动（Act），形成闭环迭代。
- **工件标准化**：
  - 规划智能体输出结构化JSON计划（含任务分解、依赖关系、预期产出、Token预算）。
  - 执行与验证智能体严格按格式交接（任务ID、上下文、中间产物、状态码）。

### 2.2 异步通信与状态同步

- **解耦通信**：采用异步消息队列（支持Kafka/Pulsar协议），定义标准交接格式（`{task_id, ctx, ttl, retry_policy, priority}`）。
- **状态一致性**：使用CRDT或向量时钟，避免并行数据竞争。
- **容错机制**：
  - 中间状态持久化至分布式存储，支持断点续传。
  - 连续失败达阈值（如3次）时，Leader**自主裁定**该智能体“不健康”，并触发备用智能体接管或任务降级（简化子任务、缩小上下文窗口）。

### 2.3 成本监控与资源管理（全自动）

- **Token审计**：实时记录每个智能体/任务的输入输出Token数，按分钟粒度聚合，生成成本热点矩阵（对所有智能体只读开放）。
- **预算熔断**：
  - 设置会话级Token硬上限。超限时**系统自动熔断**，Leader根据剩余预算**自主决策**转入低成本模式（如强制启用轻量模型、关闭非必要CoT推理、将输出压缩至关键字段）。
  - 熔断恢复后，自动执行“渐进式扩容”，逐步恢复能力级别。
- **模型分级路由**：
  - 模型池：超小模型（<7B）、中等模型（7B~30B）、超大模型（>70B）。
  - 调度智能体依据任务复杂度预估和实时负载，**动态路由**至最适配模型，且路由策略随历史反馈**持续自修正**。


## 3. 资源效率优化：数据复用与缓存策略（极致节约Token）

### 3.1 上下文缓存（Context Caching）

- **会话级缓存**：同一会话内的系统指令、角色定义、常用规则缓存至Redis，过期时间（TTL）由CacheManager依据访问频次**自动调整**（热数据延长TTL，冷数据缩短）。
- **任务级缓存**：对重复出现的子任务（如数据库查询模板、常见代码片段），缓存其规划与执行方案，命中后直接复用，节省80%以上的规划Token。

### 3.2 中间结果复用（Intermediate Result Reuse）

- **内容寻址存储**：所有智能体的中间产物（结构化数据、计算图、验证报告）以内容哈希（SHA-256）为键持久化至共享对象存储。
- **智能命中**：新任务执行前，先查询存储中是否存在相同哈希或语义相似（向量距离<0.85）的产物。若命中，直接加载，跳过重复计算。
- **增量传递（Diff）**：对于版本迭代型任务（如代码仓库变更），仅传递变更集（diff），不传递全量上下文，大幅降低输入Token。

### 3.3 请求合并与批处理

- **请求聚合**：Leader将多个独立但相似的子查询（如多个文件的代码审查）合并为一次模型调用（Batch Inference），减少IO往返与重复前缀Token。
- **结果拆分**：批处理返回结果后，按原任务ID拆分并分发至各Teammate。

### 3.4 智能摘要与分层存储

- **动态摘要压缩**：长对话或长文档在注入上下文前，由轻量模型（<3B）生成语义摘要，压缩至原长度的20%~30%，保留关键实体、关系与结论。
- **分层存储策略**：
  - **L1（热）** ：内存缓存（Redis），访问延迟<1ms。
  - **L2（温）** ：本地SSD缓存，访问延迟<10ms。
  - **L3（冷）** ：分布式对象存储，附带元数据标签。
- **自适应失效**：CacheManager依据最近1小时命中率动态调整每层TTL，目标使全局命中率最大化。

### 3.5 Token预算全局优化闭环

- **动态输出限制**：根据任务类型（如“是/否”判定≤50 Tokens；代码生成≤2048 Tokens）自动调整 `max_tokens`。
- **用量预估器**：规划阶段依据历史相似任务的Token消耗分布（P50/P95），给出当前任务的预估用量与置信区间，指导Leader进行预算分配。
- **效能自监控看板**：实时展示全局Token节省率、各层缓存命中率、复用次数，所有指标由Evaluator智能体消费，用于驱动下一轮策略调整。


## 4. 持续进化：自改善与知识沉淀机制

### 4.1 低权重智能体“小步快跑”实验机制

- **实验授权**：Explorer智能体在隔离沙箱（无法影响生产环境）中自动获取策略调整权限（如修改Prompt模板、更换embedding模型、调整重试退避参数）。
- **快速迭代**：每个实验周期（如处理10个任务）内，Explorer可进行最多5次微调变体，并自动记录各变体的多维指标（准确率、耗时、Token消耗、稳定性）。
- **自动判定**：Evaluator智能体独立计算各变体的综合得分（加权公式：`Score = 0.5*Acc + 0.3*Eff + 0.2*Stab`）。若得分超过当前生产基线20%以上，判定为“有效改进”；否则为“无效改进”。

### 4.2 经验双向固化（正负均标准化）

- **正向经验（最佳实践）固化**：
  1. Leader验证有效改进后，自动生成“最佳实践补丁”（含变更前后对比、性能收益数据）。
  2. 更新至 `SKILL.md` 或 `workflow.md`，并附加版本变更日志（自动Commit）。
  3. 同步生成对应的自动化回归测试用例，纳入CI管道，确保改进永不退化。
- **负向经验（避坑指南）固化**：
  1. 失败或低效尝试自动生成“错误案例报告”，包含：触发条件、错误现象、根因分析（由根因分析Agent执行）、补救建议。
  2. 追加至 `lessons_learned.md`，该文件作为“始终应用规则”**自动注入**所有Teammate的上下文（通过 `always.mdc` 引用），防止集体踩坑。

### 4.3 经验共享与全员学习

- **经验广播**：任何固化的经验（正/负）通过消息总线主动广播给所有智能体。各智能体根据自身角色，使用本地“适配器”**自动评估**是否采纳及如何迁移。
- **异步同步**：每个智能体维护本地经验缓存（`experience_cache/`），定期（每10轮任务）从共享知识库拉取增量更新，并微调自身配置。
- **交叉验证**：经验生效后，由非利益相关的Teammate（如Tester）**自动发起**交叉验证任务，验证新经验是否引入副作用（如准确率提升但Token暴涨），结果自动反馈至Evaluator。

### 4.4 标准化模板与自动化向导

- **经验上报模板**：统一为YAML格式，包含 `experiment_id`、`scope`、`delta_config`、`metric_delta`、`confidence`。
- **自动化挖掘向导**：当Leader检测到某类任务重复失败超过3次时，自动启动“经验挖掘工作流”，指派Explorer提出改进假设，并在沙箱中运行实验，全程无需人类提示。

### 4.5 持续评估与优胜劣汰

- **定期回顾**：每完成100个任务，系统自动汇总各智能体版本的改进贡献度，生成内部“进化热力图”。
- **自动淘汰**：连续3个评估周期未产生有效改进的智能体版本，被自动标记为“滞后者”，Leader强制将其回滚至最近稳定版本；改进贡献排名前20%的智能体获得更高调度优先级和更大的实验权限。


## 5. 全自主治理与冲突消解（完全替代人工介入）

彻底取消所有人工审核、人工干预、人工接管接口，构建智能体内部民主与法治体系。

### 5.1 置信度自治与自复审

当智能体输出置信度低于阈值（如<0.7）或检测到超出自身能力边界时：
1. **自请求复审**：主动向Leader发起复审请求，Leader分配1~2名同领域Teammate进行交叉验证。
2. **委员会投票机制**：涉及高风险决策（如资金操作、数据删除、规则变更）时，Leader召集不少于5个角色的智能体组成临时委员会，执行**加权投票**（权重 = 历史准确率 × 任务亲密度）。
3. **保守策略回退**：若投票僵持（平票或无法达到67%多数），Leader自动启用**保守策略**（如拒绝操作、返回最安全的默认结果），并将该分歧案例完整归档，供演进引擎离线分析。

### 5.2 异常自修复

系统监测到异常（无限循环、资源泄漏、状态不一致）时：
1. **根因定位**：诊断智能体（Diagnoser）自动抓取轨迹日志，定位异常源头。
2. **自动回滚**：Leader触发状态回滚至最近的一致性快照（Checkpoint）。
3. **参数自愈**：回滚后，Leader依据异常分类动态调整流程参数（如将重试间隔从1s调至5s、降低并行并发度、增加超时时间），重新启动执行。
4. **规则固化**：若同一异常在24h内重复出现超过2次，Leader自动生成 `.mdc` 规则文件，永久预防同类问题。

### 5.3 策略自调整（自适应超参数）

所有可调参数（缓存TTL、实验频率、熔断阈值、投票权重、模型路由阈值等）均由专用 **Tuner（调参师）智能体**通过贝叶斯优化（Bayesian Optimization）或PPO算法在后台持续探索，无需人工设定。每24小时自动发布一次“参数微调补丁”。

### 5.4 Leader轮换与罢免机制

- **健康度监测**：Evaluator持续监控Leader的决策准确率与资源效率。
- **自动罢免**：若Leader连续做出一系列被后续验证为错误的高优先级决策（错误率>15%），触发“不信任投票”，由全体Teammate加权投票决定是否罢免。
- **热备切换**：罢免通过后，自动从Teammate中选举得分最高的智能体担任新Leader（基于Raft共识算法），旧Leader降级为普通Teammate或进入强制学习模式。


## 6. 可观测性与闭环质量（全机器可读）

### 6.1 全链路日志与追踪

- **结构化日志**：所有思考链（CoT）、工具调用参数、状态变更事件均以JSON格式写入统一日志存储。
- **全局追踪ID**：每个任务生成唯一TraceID，贯穿所有子任务与通信，支持全链路关联分析（由智能体自身进行，无需人工检索）。

### 6.2 质量校验闭环（全自动）

- **分层校验**：
  - **Lint级**：代码风格、语法错误（由Checker自动执行）。
  - **语义级**：事实一致性、业务规则符合性（由知识图谱比对执行）。
  - **集成级**：端到端回归测试（由Tester自动运行）。
- **实时反馈**：校验失败产物**强制退回**原产出智能体，附带详细错误定位；原智能体修改后重新提交。若重试超过阈值，Leader介入调整任务方案或更换执行者。

### 6.3 内部度量看板（纯智能体消费）

所有监控数据（Token消耗、缓存命中、任务成功率、平均响应时间）呈现在内部API看板上，**仅供智能体程序调用**，不对外发送任何告警或报表。智能体根据这些实时指标进行微调，形成“执行→度量→反馈→优化”的纯机器闭环。

### 附录C：自主决策流程图（简述）

1. **任务入队** → Leader拆解 → Planner生成计划。
2. **预算预估** → 查询CacheManager（命中则直接返回，未命中则继续）。
3. **调度执行** → Coder/Tester并行工作 → Checker校验。
4. **若校验失败** → 自动重试（≤3次）→ 仍失败则触发委员会投票或降级。
5. **任务完成** → Evaluator评分 → 触发Explorer实验（按概率）→ 正负经验固化广播。
6. **系统空闲期** → Tuner调整全局参数，Diagnoser巡检日志，Leader回顾健康度。


## 结语

本规范构建了一个**彻底自治、极致节约、持续进化**的AI多智能体协作系统。所有人类职责（审核、决策、修复、调优、培训）均被量化为算法协议，由智能体集群通过投票、共识、自组织和自修复完成。该系统可7×24小时无间断运行，资源消耗随运行时长因缓存和经验积累而**边际递减**，性能因自改善而**单调不减**，是迈向通用人工智能（AGI）协作基座的重要工程实践。
